# Отчёт по SemDatasheet

## 1. Постановка задачи

Цель проекта — построить сервис поиска характеристик электронных компонентов в PDF datasheet.  
Пользователь вводит естественный запрос, например:  
`Максимальное напряжение питания MCP6002`

Сервис должен:
- найти релевантные фрагменты datasheet;
- извлечь целевое значение;
- вернуть короткий сниппет с номером страницы, именем документа, значением, единицей измерения и скором.

## 2. Выбор данных

В качестве источника данных используются PDF datasheet из каталога `data/raw`.

Ключевое допущение:
- обрабатываются только PDF с текстовым слоем;
- сканы без OCR пропускаются, чтобы не усложнять pipeline и не вносить шум.

Для оценки качества рекомендуется подготовить `data/eval` с ручной разметкой:
- запрос;
- ожидаемый документ;
- ожидаемая страница;
- ожидаемое значение.

## 3. BM25 и векторный поиск

### BM25
Плюсы:
- хорошо работает на точных терминах, артикулах, обозначениях, единицах;
- простая и быстрая модель;
- не требует GPU.

Минусы:
- хуже справляется с перефразированием;
- чувствителен к формулировкам запроса.

### Векторный поиск
Плюсы:
- лучше понимает смысл запроса;
- устойчив к перефразированию на русском и английском;
- полезен, когда пользователь пишет вопрос не дословно как в datasheet.

Минусы:
- может возвращать семантически похожие, но не точные фрагменты;
- требует эмбеддингов и внешней модели.

### Гибридный поиск
Гибридная схема объединяет оба подхода и обычно даёт лучший баланс:
- BM25 повышает точность для артикулов и единиц;
- векторный поиск повышает recall на естественных запросах;
- итоговый скор вычисляется как взвешенная сумма.

## 4. Recall@k

Формула:

`Recall@k = количество запросов, для которых релевантный ответ попал в top-k / общее число запросов`

## 5. Выводы

1. BM25 даёт сильный baseline для datasheet-задач, где важны точные совпадения по словам и единицам.
2. Векторный поиск полезен для естественных вопросов и сокращает зависимость от точной формулировки.
3. Гибридный поиск лучше всего подходит для production-сервиса, так как объединяет точность и семантику.
4. Для реального сравнения качества нужен размеченный eval-набор с вопросами и целевыми страницами.
